Notebooks

Every tool from the lab has a Google Colab notebook: a worked example that runs in your browser on Google's machines, with nothing to install and no GPU of your own. Each one walks through a real case first, then shows how to point the same steps at your own sequence, structure or trajectory.

Two of them need a GPU runtime, which Colab provides free; the rest run on a plain CPU runtime. Opening a notebook does not change it — your copy is yours, and the original stays as it is.

Predicting and sampling structures

Getting models of a complex, and deciding which of them to believe.

  • MinnieFold

    GPU runtime Open in Colab Repository Paper

    Predicts a complex eleven different ways — three AlphaFold2 versions, different recycle counts, templates on and off — and ranks the models on the chain you actually care about rather than on a whole-complex score an antibody can inflate. It is a fiftyfold-reduced version of massive sampling, built for targets with shallow alignments. The notebook builds the alignment once and reuses it, and resumes if Colab disconnects.

  • AF2Rank

    GPU runtime Open in Colab Repository

    Scores structures you already have by feeding each one back to AlphaFold2 as a template and asking how well it recognises it — a way of ranking models that does not depend on how they were made. Reports actifpTM and interface metrics side by side in one table. Runs the 1BRS example, or your own FASTA and structures.

Reading an interface

Taking a complex apart: which residues matter, which contacts last, and what the prediction knew that its coordinates do not show.

  • PROT-ON

    CPU runtime Open in Colab Repository Web server Paper

    Mutates every position on one side of an interface, scores each mutation, and flags the outliers — the handful that would strengthen binding, and the handful that would abolish it. Filters them for stability and, optionally, for whether evolution has ever tried them. The notebook adds a HADDOCK3 rescoring of the same mutations as a second opinion.

  • DynaPIN

    CPU runtime Open in Colab Website Repository Paper

    An interface is usually reported as a list of contacts read off one structure. Over a trajectory that list is not fixed: some contacts hold throughout, others open and close. DynaPIN measures which is which, along with how each residue's exposure and secondary structure change, and how the interaction network shifts frame by frame.

  • DistoFlex

    CPU runtime Open in Colab Repository Paper

    AlphaFold predicts a distribution of distances for every residue pair, then collapses it into one set of coordinates. The distribution often knows more than the coordinates do: across a hinge it stays broad, and keeps weight on the bound conformation even when the model is of the unbound protein. The notebook reproduces that on a published case before you try your own.
